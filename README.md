# Artly

Turn a photo into illustrated art. Pick one of twelve styles, add a photo, and Artly returns a reimagined version generated by Google's Gemini image model.

## Overview

Artly is a small web app I built to explore image-to-image generation with a clean, focused interface. The front end is a single page of plain HTML, CSS, and JavaScript with no build step or framework. The only server-side piece is one serverless function that forwards a photo and a style prompt to the Gemini API and returns the generated image.

I kept the scope deliberately narrow: choose a style, provide a photo, get a result. There is no account system, database, or third-party analytics.

## How it works

1. You pick one of twelve art styles from the gallery.
2. You add a photo, either by uploading a file (JPG, PNG, or WebP) or capturing one with your camera.
3. The browser sends the style ID, the photo as base64, and its MIME type to `/api/generate`.
4. The serverless function looks up the matching prompt, calls the Gemini image model with the prompt and your photo, and returns the generated image.
5. The result appears in the page, and you can download it or try another style with the same photo.

The style prompts live on the server in `api/generate.js`, so the browser only ever sends a style ID rather than the prompt text itself.

## Verified features

- Twelve selectable art styles, each with a preview thumbnail.
- Photo input by file upload or live camera capture.
- Client-side preview of the selected photo, with a retake option for camera shots.
- Image generation through a single `/api/generate` serverless endpoint.
- Download of the generated image.
- "Try another style" flow that keeps the current photo in place.
- Optional background music toggle in the hero area.
- Server-side validation of style, image payload, MIME type, and payload size.

## Design approach

The interface is a single vertical flow — hero, style gallery, photo input, and result — so the steps read top to bottom. Typography uses Lora, Inter, and JetBrains Mono (loaded from Google Fonts), and the styling leans on a warm, editorial look. All layout and styling is hand-written CSS in `styles.css`. Interactive controls include ARIA labels and keyboard handlers for selection and the music toggle.

## Technology stack

- **Front end:** HTML, CSS, and vanilla JavaScript (no framework, no bundler).
- **Back end:** a single Node.js serverless function (`api/generate.js`).
- **Image generation:** Google Gemini (`gemini-2.5-flash-image`) via the Generative Language API.
- **Hosting/config:** Vercel (`vercel.json`).
- **Tooling:** a Python standard-library script for project validation.

## Local setup

The page itself is static, but image generation depends on the serverless function and a Gemini key, so the app is best run with the Vercel CLI:

```bash
# From the project root
cp .env.example .env        # then add your real key
vercel dev
```

`vercel dev` serves `index.html` and the `/api/generate` route together. You can also open `index.html` through any static file server to review the UI, but generation will only work when the serverless function and `GEMINI_API_KEY` are available.

## Environment variables

| Variable | Used by | Purpose |
| --- | --- | --- |
| `GEMINI_API_KEY` | `api/generate.js` | Authenticates requests to the Gemini image model. Read from `process.env.GEMINI_API_KEY` on the server and never sent to the browser. |

Copy `.env.example` to `.env` for local development, and set the same variable in your Vercel project settings for deployment.

## Project validation

A small standard-library Python script checks the project structure without changing anything:

```bash
python scripts/validate_project.py
```

It verifies that required files exist, that every local image and audio reference in `index.html` and `app.js` resolves to a real file, that no `.env` or secret-like files are tracked by git, and that `.env.example` contains only placeholder values. It exits with a non-zero status if any critical check fails.

## Deployment

The project is set up for Vercel. `vercel.json` gives the `api/generate.js` function a 60-second maximum duration and sends `Cache-Control: no-store` on `/api/*` responses. Deployment requires `GEMINI_API_KEY` to be configured as an environment variable in the Vercel project.

## Technical decisions

- **Keep the API key server-side.** The key is only read inside the serverless function and is never exposed to the client.
- **No caching for the API.** `/api/*` responses use `no-store` so generated images are not cached.
- **Validate input before calling Gemini.** The function checks the style ID, presence of image data, allowed MIME types (JPG, PNG, WebP), and a payload-size limit before making the request.
- **No build step.** Plain HTML, CSS, and JavaScript keep the project easy to read and deploy.

## What I learned

- Structuring an image-to-image flow end to end, from browser input to a serverless call and back.
- Handling image input in the browser with both file uploads and the camera (`getUserMedia`, canvas capture, base64 encoding).
- Working with the Gemini Generative Language API and its request/response shape for image output.
- Keeping secrets on the server and being deliberate about caching and input validation.
